# Batch Job Dashboard

A production-grade, full-stack web application for monitoring and managing scheduled batch jobs. Replaces manual Excel-based tracking with a centralized dashboard featuring sorting, filtering, search, batch detail views, and server command references.

---

## Quick Start

### 1. Clone and install dependencies

```bash
# Install server dependencies
npm install

# Install client dependencies
cd client && npm install && cd ..
```

### 2. Configure environment

```bash
cp .env.example .env
# Edit .env if you need to change the port or file path
```

### 3. Generate sample data

```bash
npm run generate-sample
# Creates data/batches.xlsx with 10 realistic mock records
```

### 4. Run in development mode

```bash
# Starts both the Express backend (port 4000) and Vite dev server (port 3000)
npm run dev
```

Open **http://localhost:3000** in your browser.

The Vite dev server proxies all `/api` requests to `http://127.0.0.1:4000` — no CORS configuration needed in development.

### 5. Production build

```bash
# Build the React app
npm run build:client

# Start the Express server (serves the built React app)
NODE_ENV=production npm start
```

Open **http://localhost:4000** in your browser (or your configured `PORT`).

## Excel File Schema

The application expects an Excel file with the following column headers (exact header names by default):

| Column Header    | Internal Field   | Type           | Notes                                        |
|------------------|-----------------|----------------|----------------------------------------------|
| `Batch_ID`       | `batchId`        | string         | Required. Must be unique.                   |
| `Batch_Name`     | `batchName`      | string         | Required.                                    |
| `Description`    | `description`    | string         |                                              |
| `Domain`         | `domain`         | string         | `Benefits` or `Tax`                         |
| `Frequency`      | `frequency`      | string         | `Daily`, `Weekly`, `Monthly`, or `Ad-hoc`  |
| `Schedule_Time`  | `scheduleTime`   | string         | `HH:MM` or cron expression                  |
| `Last_Run_Time`  | `lastRunTime`    | date/string    | Excel date or `YYYY-MM-DD HH:MM:SS`         |
| `Next_Run_Time`  | `nextRunTime`    | date/string    | Excel date or `YYYY-MM-DD HH:MM:SS`         |
| `Last_Run_Status`| `lastRunStatus`  | string         | `Success`, `Failed`, `Running`, `Skipped`   |
| `Environment`    | `environment`    | string         | `DEV`, `QA`, or `PROD`                      |
| `Owner_Team`     | `ownerTeam`      | string         |                                              |
| `Start_Command`  | `startCommand`   | string         | Shell command to start the batch             |
| `Stop_Command`   | `stopCommand`    | string         | Shell command to stop the batch              |
| `Status_Command` | `statusCommand`  | string         | Shell command to check batch status          |
| `Log_Path`       | `logPath`        | string         | Path to batch log file                       |
| `Config_Path`    | `configPath`     | string         | Path to batch configuration file             |
| `Notes`          | `notes`          | string         | Free-form notes                              |

Multiple sheets are supported — rows from all sheets are merged.

---

## Column Mapping Configuration

If your Excel file uses different column header names (e.g., `BatchID` instead of `Batch_ID`), edit `server/config/columnMapping.config.js`:

```js
module.exports = {
  // Excel column header  :  internal model field
  BatchID:      'batchId',     // ← changed from Batch_ID
  BatchName:    'batchName',   // ← changed from Batch_Name
  // ... rest unchanged
};
```

No other files need to change. The mapping is applied at parse time inside `server/utils/fileParser.js`.

## API Reference

All endpoints are prefixed with `/api`.

| Method | Path                                        | Description                          |
|--------|---------------------------------------------|--------------------------------------|
| GET    | `/api/batches`                              | Return all batches                   |
| GET    | `/api/batches/summary`                      | Return dashboard summary stats       |
| GET    | `/api/batches/search?q=<query>`             | Full-text search across all fields   |
| GET    | `/api/batches/filter?domain=&frequency=&status=` | Filter by one or more criteria  |
| GET    | `/api/batches/:id`                          | Return single batch by Batch_ID      |
| POST   | `/api/upload`                               | Upload `.xlsx` file (multipart)      |
| GET    | `/health`                                   | Health check                         |

## Features

- **Summary Cards**: Total, Active, Inactive, Running Today, Failed, By Domain — with Recharts pie charts
- **Sortable Table**: Click any column header to sort ascending → descending → reset
- **Global Search**: Debounced full-text search across all batch fields
- **Filter Panel**: Dropdown filters for Domain, Frequency, and Status with removable chips
- **Batch Detail Modal**: Click any row for a tabbed modal showing metadata and commands
- **Full Detail Page**: `/batch/:id` route for a standalone detail view
- **Command Viewer**: Code-block UI with per-command copy-to-clipboard
- **Excel Export**: Export currently filtered data back to `.xlsx` via the Export button
- **Excel Upload**: Replace the live data store at runtime via the Upload Excel button
- **Dark Mode**: Toggle via the sun/moon icon in the header
- **Responsive**: Table on desktop, card list on mobile viewports

## Assumptions

1. **Unique Batch_ID**: `Batch_ID` is used as the primary key. Duplicate IDs in Excel will result in the last occurrence being used.
2. **Active status**: Derived from `Last_Run_Status` — `Success` or `Running` = Active; anything else = Inactive.
3. **Date columns**: Excel date serial values are automatically converted to ISO strings by the `xlsx` library when `cellDates: true` is set.
4. **Multi-sheet workbooks**: All sheets are parsed and merged; the column mapping must apply to all sheets.
5. **No authentication**: This is an internal read-only dashboard with no login flow.
6. **No database**: All data is held in process memory. Restarting the server reloads from the Excel file path configured in `.env`.
7. **File upload replaces data**: Uploading a new Excel file replaces the entire in-memory store (not appends).
